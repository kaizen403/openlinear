# OpenLinear API

## Home Chat backend

The `/api/chat` module powers the workspace home chat. It is intentionally data-grounded: the system prompt tells the model to call tools for every workspace, project, team, issue, label, comment, member, count, or status answer, and the tools re-check the same database permissions used by the REST API. The model is configured only on the server; the client never sends model names or provider keys. `CHAT_LLM_BASE_URL`, `CHAT_LLM_API_KEY` (or the legacy `FIREWORKS_API_KEY`), `CHAT_LLM_MODEL`, `CHAT_LLM_TITLE_MODEL`, `CHAT_LLM_PROVIDER`, timeouts, retry bounds, cache hints and `MODEL_PRICING_JSON` are validated in `src/lib/chat-llm-config.ts`, which also documents the default data processor (Fireworks AI, `kimi-k2p6`) and exactly what each request sends to it. An invalid value disables chat with `LLM_MISCONFIGURED` instead of silently falling back. `CHAT_RATE_LIMIT_PER_MIN` still bounds messages per user.

Tool surface: 34 registered tools, each classified by effect (`read`, `write`, `destructive`, `external`). Reads and ordinary writes run directly. Destructive tools (`bulk_update_issues`, `archive_issues`, and the access/role tools, which stay withheld) never change anything on the first call: they return the exact selection and a single-use, 10-minute `CONFIRM-XXXXXXXX` code bound to that selection and change, and run only when called again after the user's own message (or the message body's `confirmationTokens`) contains the code. There are no delete tools. Tool calls are journaled by a server-assigned per-turn id, never by the provider's id alone. Bulk issue generation uses a preview-first `dryRun` pattern so brainstormed plans can be rendered before commit.

Every model call (each round, retry, failure and title) is recorded in `model_usage` with provider-reported tokens, cache reads and a cost basis (`provider_reported`, `estimated` from `MODEL_PRICING_JSON`, or `unknown` with a null cost). `GET /api/usage/models` reports the caller's own usage.

`POST /api/chat/sessions/:id/messages` returns Server-Sent Events. Chunks use event types such as `assistant_delta`, `tool_call_start`, `tool_result`, `confirmation_required`, `assistant_final`, `error`, and `done` (which carries a `usage` summary when the provider reported tokens). Sessions are scoped to one workspace and optionally one project, and every session query filters by the authenticated user plus workspace membership to prevent cross-workspace leakage.
