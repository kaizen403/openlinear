# OpenLinear: backend agent evaluation and runtime research

> Source evidence includes the pre-fix audit. Read [consolidated validation](validation.md) for final repairs, tests and remaining scope. Audit line references may precede the local edits.
Research date: 2026-10-15. Primary sources were opened on this date. Undated documentation below is a live snapshot, not a dated release guarantee. No inference evaluations, paid calls, deployments, or external mutations were performed during research. The older Desktop revamp plan was treated as a set of hypotheses, not current evidence.

## What a credible superiority claim would require

OpenLinear is an agent harness and orchestration product. Its performance depends on model, runner, context policy, tools, resources, and inference budget. A higher public leaderboard score from a different model or budget does not establish a better OpenLinear backend. Report named configurations and a bounded result, for example: “OpenLinear configuration X improved pass@1 over Codex CLI version Y on dataset revision Z under budget B.” Do not claim general superiority over Codex, Claude, or Devin from a terminal microbenchmark, mock runner, smaller development subset, or undocumented vendor score. Anthropic explicitly distinguishes the evaluation harness from the agent harness and the final environment outcome from the agent's success message. [Agent evaluation terminology](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents).

Two experiments are required:

1. **Harness experiment:** fixed underlying model and provider configuration, compare OpenLinear integration against the same native runner without OpenLinear enhancements; then ablate individual context/recovery/verifier/routing changes. This isolates harness contribution as far as the runner permits.
2. **Product experiment:** compare complete named stacks under the same environment and budget contract. Different native tools and prompts are part of the treatment. Report the actual model/router choices; this measures the stack, not model capability alone. If a closed service conceals model, tokens, or costs, state the missing data and do not make a token-matched or cost-matched claim.

## Harbor integration and observability

Harbor currently documents preintegrated `codex`, `claude-code`, `opencode`, and `devin` agents, ATIF trajectory support, repeated attempts, custom installed/external agents, and separate verifiers. [Agents](https://docs.harborframework.com/agents/pre-integrated-agents), [custom agents](https://docs.harborframework.com/agents/custom-agents), [job configuration](https://docs.harborframework.com/jobs/configs), [separate verifier](https://docs.harborframework.com/tasks/separate-verifier).

Implement an OpenLinear adapter that invokes the real backend runner contract inside Harbor's task boundary, without live OpenLinear credentials or production API state. Preserve raw native trajectory plus normalized ATIF, patch, task artifacts, event journal, and accounting. Smoke-check adapter conformance using nop/oracle reference gates before purchasing inference runs. Freeze Harbor release and full Git SHA, adapter SHA, runner executable and SDK versions, installation artifact checksums, and native configuration. Never use floating `latest` in scored runs.

The [Harbor Devin adapter source](https://github.com/harbor-framework/harbor/blob/main/src/harbor/agents/installed/devin.py) explicitly installs and runs **Devin CLI**, records its version and native session DB, and estimates USD from ACUs. This is not Devin Cloud. Cost reconciliation must preserve ACU totals and price basis, rather than treating the adapter's estimated conversion as an invoice. A Cloud comparison needs a separately named surface, environment contract, artifacts, and accounting; if controls cannot be matched, publish a separate observational track.

## Runtime lessons, with boundaries

**OpenCode.** [Server](https://docs.opencode.ai/docs/server/) confirms a headless OpenAPI HTTP server, localhost default and optional Basic auth. [SDK](https://docs.opencode.ai/docs/sdk/) exposes typed sessions, abort, messages, children, summary and permission responses. [Config](https://docs.opencode.ai/docs/config/) documents config merging and `OPENCODE_CONFIG_CONTENT` runtime overrides; auto compaction defaults true, pruning currently defaults false, and reserved context is configurable. [Permissions](https://docs.opencode.ai/docs/permissions/) currently says repeated identical calls and external paths ask for approval, while `.env` reads default deny. Consequently, old plan claims that `.env` reads always ask and tool-output pruning is automatically enabled are stale. Handle native approvals and questions with explicit deadlines/states; inject and record resolved configuration; subscribe before dispatch; reconcile stream reconnects against native state; separate heartbeat liveness from task progress. Directory-scoped sessions are organizational scoping, not a tenant sandbox. Host-level isolation remains necessary.

**Claude Agent SDK.** [Overview](https://code.claude.com/docs/en/agent-sdk/overview) documents built-in tools, agent loop, context management, sessions, hooks and permissions, with an operated subprocess rather than a new tool loop to reimplement. [Sessions](https://code.claude.com/docs/en/agent-sdk/sessions) distinguishes explicit resume IDs, session-store persistence and filesystem state: conversation fork does not fork the working tree. [Loop](https://code.claude.com/docs/en/agent-sdk/agent-loop) documents parallel readonly tools, sequential mutation tools, automatic compaction and budget overshoot by an in-flight response/subagents. [Accounting](https://code.claude.com/docs/en/agent-sdk/cost-tracking) documents automatic prompt caching, distinct cache-read/write fields, ID deduplication and per-query result totals. Keep native runner context handling behind the adapter, add application-owned acceptance criteria/checkpoints, isolate each run's config and files, and count all helper/subagent work. Dollar ceilings require reserved headroom; a polled usage estimate alone is not an exact hard cap.

**Isolation.** [Secure deployment](https://code.claude.com/docs/en/agent-sdk/secure-deployment) describes OS sandboxes, containers and VMs with different isolation strengths. Application permission hooks complement the execution boundary. For remote untrusted multi-tenant code, use an explicit sandbox contract for filesystem, processes, resources, credentials, egress and lifetime. Never rely on model instruction or a worktree to contain a subprocess. Benchmark verifiers should consume selected artifacts in a clean environment and own the grading files.

**Context and recovery.** [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (Sep 29, 2025) supports concise high-signal context, just-in-time file retrieval, compaction and structured notes. [Long-running harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (Nov 26, 2025) reports that compaction alone does not ensure coherent progress; incremental verifiable units and handoff artifacts help. [Managed-agent architecture](https://www.anthropic.com/engineering/managed-agents) (Apr 8, 2026) separates an append-only session log, changeable harness and sandbox, and cautions that model improvements can make old scaffolding unnecessary. Adopt durable goal/acceptance/decision/test state, reference-addressed large outputs, journaled compaction and idempotent tool effects. Resume only after reconciling real sandbox/session state. Measure recovery with fault injection, not mocked happy-path completion. Keep caching/model-routing/planning changes independently configurable and ablate them under fixed budgets.

**Devin practices.** [Prompting guidelines](https://docs.devin.ai/essential-guidelines/instructing-devin-effectively) emphasize explicit scope, existing patterns, acceptance criteria and frequent test/build feedback. [Blueprints](https://docs.devin.ai/onboard-devin/environment/blueprints) describe declarative tools/dependencies/commands and fresh bootable snapshots, with post-build checks and snapshot pinning. [Session Insights](https://docs.devin.ai/product-guides/session-insights) examines repeated build/environment failures and encourages fixing setup and outdated knowledge. Adopt versioned repository setup and validated dependency caches; do not repeatedly charge every task for avoidable provisioning errors. Mine failed development trials for general environment/skill improvements, but prohibit learning from sealed evaluation cases.

## Proposed reproducible evaluation specification

1. **Suites and splits.** Freeze TB 4.0.0 full manifest as a public general-terminal test. Freeze SWE-bench Pro V2 public `test` with locked replay as repository test. Add privately authored recent backend tasks for OpenLinear's actual workload: API tenancy/auth, SQL migrations, async execution, SSE, cancellation/recovery, Git workflows and distributed failures. Each task has repo/base commit, original user-style issue, permitted tools/network, independent hidden tests, explicit acceptance rubric, reference solution and empty-patch negative gate. Partition private tasks by repository and time into development, validation and sealed release holdout. Author tests independently of OpenLinear output; reject ambiguous/flaky tasks before system comparisons. Pilot sample size, then preregister a power calculation from paired task disagreements; do not promise a three-point lead from a small suite.

2. **Baselines.** Compare pinned Codex CLI, Claude Code CLI, OpenCode and Devin CLI, naming exact model/effort/provider. Include “OpenLinear + native runner, enhancements off” to detect integration regressions. Add same-model comparisons where available. Disable unreported adaptive routing; otherwise record router and every model used. A separate best-config product track may allow routing/subagents, but all consumption counts.

3. **Two budget tracks.** Official-fidelity public track uses each frozen benchmark's published environment/time/network protocol: TB currently eight hours and SWE-bench Pro V2 fifty minutes. Do not rename a budget-restricted variant as an official leaderboard run. A separate product track preregisters common caps, proposed starting point: 50 minutes agent elapsed time, USD 10 inference and 1,000,000 aggregate model tokens per task, stopping at the first cap. Include model/helper/subagent/retry/context-compaction tokens, cache reads/writes and reasoning where reported; preserve native and normalized fields since tokenizers differ. The setup/queue/verifier time is separately reported and also included in end-to-end task-to-artifact latency. Benchmark all stacks at several fixed caps to produce a cost/latency/success frontier; tune caps on development only. If accounting prevents enforcement, exclude that stack from the relevant matched-budget claim and present it separately.

4. **Pinned manifest.** Store dataset revision/config/split/task IDs and checksums; harness/adapter/repo SHAs; OCI image digests; runner and SDK versions; model snapshot ID, provider endpoint/region, effort, sampling parameters, max output/context policy; prompts/tool schemas/skills/MCP config and hashes; sandbox CPU/RAM/storage/architecture/headroom/egress; concurrency; cache policy; budget/stop rules; retry policy and verifier revision. Resolve aliases before start and reject changed manifests. Save prices with date and measured/estimated/invoiced cost basis. Record unexpected service changes rather than silently merging them with prior results.

5. **Repeated first attempts.** Five independent trials per task/config for release evidence, randomized interleaved order. Fresh sandbox/session each trial; use supported sampling seed and task/run seed, but acknowledge APIs without deterministic seeds. Never select the best of five as pass@1. Report mean single-attempt success, per-task outcomes and per-seed distribution. A separate pass@k metric is permitted only with its additional budget and selection/verification mechanism explicitly named.

6. **Contamination controls.** Evaluation-only task/verifier storage; no gold solutions or hidden tests in agent context; sanitize future git history/refs and dependency artifacts; disable external solution lookup according to suite rules and log/probe egress. Public benchmarks are not provably uncontaminated, even with clean local context. Freeze development/holdout access, record model knowledge/cutoff claims as unverified provider declarations, audit memorized benchmark artifacts and suspicious solver behavior, and reserve new private tasks whose solutions were never published. Reset cross-task memory and caches containing task-specific outputs; stable prompt caches are allowed only under a disclosed shared policy.

7. **Independent grading.** First stop the entire process tree and snapshot artifacts. Reapply patch to pristine base image; run immutable hidden regression/acceptance tests; evaluate artifact properties and task-specific invariants. Separate executable correctness from blinded calibrated rubric review (scope, tests, security, maintainability). LLM judges are ancillary and versioned; publish reviewer agreement/calibration and adjudicate disagreements. Agent-written tests or a “done” message cannot be the only success signal.

8. **Statistics and cost.** Prespecified primary metric: pass@1 with paired delta versus each named baseline. Report task-cluster/hierarchical bootstrap 95% intervals (tasks sampled, then repeats within task) and conditional run variability; do not treat correlated repeats of the same task as unrelated new tasks. Report mean and median cost over all tasks, cost per resolved task (total spend / successes), p50/p95 end-to-end and agent latency, token/cache totals, timeouts/refusals/policy breaches/infra errors. Use censored failures in latency distributions, not only successful fast cases. Preregister practical improvement threshold and multiple-comparison treatment. No superiority claim unless the relevant paired interval and practical threshold support it on a sealed holdout and the defined resource/budget contract.

9. **Error policy.** Missing rewards, exhausted budgets and agent failures count as zero in the primary denominator. Log infrastructure classification independently. A predeclared recovery rule may rerun verified platform failures using a fresh environment, applied identically across stacks; retain all original outcomes and publish intent-to-run and adjudicated views. Never rerun failed reasoning until success. Fault-injection reliability suite separately measures event replay/deduplication, restart salvage, cancellation, budget stops, dirty-worktree handling, credential isolation and cross-tenant boundaries.

10. **Gates.** Every change: fast deterministic runner-contract/recovery tests plus offline worktree/journal microbenchmark. Nightly, once inference spending is authorized: rotating development sentinel tasks and failure triage. Weekly: validation subset with multiple repeats and component ablations. Release: full pinned public suites plus sealed private holdout, five repeats, signed configuration/results/artifacts and blinded quality review; evaluation owner freezes the stack before exposing holdout outcomes. Define noninferiority margins from baseline variance and product risk, then fail releases on correctness/policy regressions and budget-contract violations. Rebaseline explicitly when a major dataset/runner/model revision changes; never compare incompatible numbers in one trendline.

## Near-term scope

Implement an actual local offline execution microbenchmark first: controlled local git origin, measured worktree acquisition/release, SQLite journal, fake runner/coordinator event path, raw per-iteration samples and percentiles, small default fixture and explicit 300 MB opt-in. It can validate backend overhead and regressions without model spend. It excludes inference, remote network, cloud sandbox startup, real patch quality and PR publication, and therefore supplies no Terminal-Bench or task-to-PR superiority evidence. Keep the existing soak placeholder clearly pending until a real multi-run restart/cancellation/replay workload exists.
