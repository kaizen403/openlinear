## Threat model

Assets: host files/SSH and cloud credentials; OpenLinear API session/refresh keys; database and encryption secrets; user provider credentials/budget; other tenant repository code and messages; Git mirror/config integrity; device CPU/memory/disk/process inventory; authorized completion artifacts.

Adversaries: prompt-injected tasks/comments/repository instructions; repository package hooks/plugins/MCP tools; compromised dependencies; a different tenant/project author; malicious websites rebinding to loopback; ordinary local processes attempting unauthorized sidecar access. A fully privileged attacker on the host, kernel compromise, and a deliberately host-trusted project are outside a local sandbox's guarantee. The distinction between a different OS user and arbitrary code executing as the same user matters: 0700/0600 alone does not separate agent and sidecar.

Boundaries: authenticated API grants run authority → local privileged supervisor → private per-run workspace and credential set → untrusted agent/tools → authorized egress/model service. Treat runner events and completion files as untrusted input. Never derive identity from runner-supplied IDs alone; bind them to the supervisor's run lease. Every callback is scoped to `(userId, workspaceId, projectId, taskId, runId, deviceId)` from authenticated API state.

## Corrections to the Desktop Phase 3 proposal

The original plan correctly calls for a SandboxProvider, separate push credentials, fail-closed tier selection, and a control channel across the network namespace (`03-phases/PHASE-3-sandboxing-and-trust.md`; `04-infrastructure/A2-execution-engine-architecture.md:196–212`; R4 §6–7). Preserve those invariants, with these adjustments:

- HostProvider is migration scaffolding only; it cannot be the default while claiming secure execution. Persist a project trust grant with principal, revision, reason and expiry, and refuse untrusted execution if no tested provider is available. Report-only network observation is allowed only for synthetic fixtures or an explicit temporary trust grant. Read restrictions remain enforced during observation.
- Do not promise broad resource enforcement from Seatbelt/bubblewrap alone. Select providers by mandatory capabilities and expose `unsupportedLimits`; refuse a profile needing missing limits. CPU/memory/disk/pid limits require a supervisor plus appropriate OS/container support.
- Do not initialize one global mutable runtime policy for concurrent tenants. Put policy/proxies/session state in a separate supervisor process per run or immutable credential-set pool with strict run isolation, and test that cleanup/reset cannot affect another run.
- Resolve and protect the worktree `.git` file, actual gitdir, commondir, config/worktree config, hooks, alternates, attributes/filters and object stores. A shared writable bare mirror is a cross-run boundary. Prefer a dissociated per-run snapshot with protected metadata for the first isolation tranche; add shared object optimizations only after read-isolation and poison tests pass.
- Domain allowlists do not authorize HTTP methods/paths or guarantee source code cannot be sent to an allowed model host. Provider egress must use narrow host/port plus credential injection restricted to expected request headers and endpoints; never replace sentinels in arbitrary bodies. Separate model inference and dependency fetch capabilities. Broker remote Git operations outside the sandbox.

Current primary sources checked on 2026-10-15: [Anthropic runtime README](https://github.com/anthropics/sandbox-runtime/blob/main/README.md) documents macOS/Linux plus Windows alpha, default unrestricted reads, and platform-specific caveats. Its documented main API is `wrapWithSandbox`; the old plan's `wrapWithSandboxArgv` must be verified against a pinned release before implementation. [Credential schema](https://github.com/anthropics/sandbox-runtime/blob/main/src/sandbox/sandbox-config.ts) documents masking extraction defaults that can pass unmatched secrets through, and file masking that degrades to denial on macOS/Windows. Explicit `onExtractNoMatch: 'error'`/deny and `injectHosts` are required. These are upstream-main observations, not proof that any released version meets OpenLinear's policy. [Official Codex sandbox documentation](https://learn.chatgpt.com/docs/sandboxing) distinguishes write boundaries from approval behavior; `never` does not establish a host read boundary. Installed SDK source is authoritative for current env inheritance. [Git credential documentation](https://git-scm.com/docs/gitcredentials) describes multiple helpers and host/path matching; [Git config](https://git-scm.com/docs/git-config) defines inherited configuration precedence. Local argv safety does not disable subprocesses executed by Git itself.

## Incremental backend implementation

1. **Repair execution plumbing and explicit ownership first.** One coordinator owns API snapshot, workspace handle, verified runner session, journal and terminal transition. Remove Prisma and cloud signing keys from API-only sidecar runtime; initialize API client through an authenticated local handshake. Remove ambient OpenCode server fallback. Strictly filter session events before decoding. Keep every run's actual returned workspace path, full UUID branch and cleanup lease. Unknown runner/policy/version must fail rather than falling back to OpenCode/host mode.
2. **Introduce interfaces with denial as the initial secure result.** `packages/sandbox` owns validated policy and provider capabilities; `packages/execution-core` has serializable handle references, not supervisor credentials. Add policyHash/providerVersion/credentialSetId to journal runs and audit grants. The backend returns structured `SANDBOX_UNAVAILABLE`, `SANDBOX_PREFLIGHT_FAILED`, `POLICY_DENIED`, `SANDBOX_LIMIT_UNSUPPORTED` responses without executing. Existing intentional trusted-host runs need an explicit grant, not an env bypass.
3. **Implement a tested Linux provider and Mac provider separately.** Wrap the entire runner process, including in-process tools and plugins. Supply argv + env objects; if a library exposes only shell text, use only an audited fixed launcher protocol or fail rather than concatenate untrusted strings. Secure per-run HOME/config/cache/tmp; no ambient auth stores, agents, credentials, sockets, node injection or LD/DYLD variables. Allow only explicit immutable toolchain reads. Linux: namespaced network/filesystem/pid/IPC, seccomp, verified user namespace support and resource cgroup. Mac: absolute sandbox-exec, positive read/write allowlist compiled with actual tool paths, dedicated supervisor and bounded scratch. Prefer isolated container/VM where the required resource/process guarantees cannot be met.
4. **Windows remains gated by evidence.** Re-evaluate pinned srt Windows alpha using distinct account/ACL/WFP and Job Objects; verify account isolation, peer auth, named pipes, kill-on-close and egress before selection. Docker/WSL presence alone is not a safe fallback: validate mount/network boundary, host shared drives, WSL host interoperability and all required capabilities. Return unavailable where none passes. Do not silently run on the host.
5. **Credential broker and completion gate.** Credentials remain outside the agent. API authorizes a single repo/run; provider broker holds real inference key; sandbox receives only a per-run sentinel or authenticated narrow proxy capability. Host Git gets a read or push token only for its expected phase/repo/ref. Replace disk helper with authenticated private IPC and short-lived operation lease; reset inherited helpers and exclude global/system config. Hide broker socket from agent, reset/validate git config/attributes/remote destination, use minimal Git env, and use immutable completion snapshot. After reaping, stage only reviewed paths, scan content/diffs for registered secrets, commit/push the reviewed snapshot, revoke token/lease, release workspace. Revoke on cancel/failure/expiry; recovery identifies and removes abandoned leases.
6. **Uniform output sanitation and lifecycle verification.** Structured event validation precedes journal/SSE. Stateful per-run redactor buffers possible partial matches and never emits a prefix that might complete a registered secret; exact known value variants plus limited shape fallback. Apply before logs, SSE, journal, outcome, PR body and Git error surfaces. Bound buffering, nested payload depth/size and sink backpressure. Redaction is defense in depth; arbitrary encoding cannot be safely exhausted.

## Backend contracts

```ts
type RunBinding = { userId: string; workspaceId: string; projectId: string;
  taskId: string; runId: string; deviceId: string };
type SandboxPolicy = { schemaVersion: 1; mode: 'isolated' | 'trusted-host';
  filesystem: { writableRoots: string[]; readOnlyRoots: string[]; denyRoots: string[] };
  network: { mode: 'deny' | 'proxy'; endpoints: Array<{ host: string; port: number }> };
  credentials: { inherit: 'none' }; limits: { cpu: number; memoryMb: number;
    diskMb: number; wallClockMs: number; maxProcesses: number } };
interface SandboxProvider {
  preflight(policy: SandboxPolicy): Promise<PreflightResult>; // verified capabilities, blockers
  create(binding: RunBinding, policy: SandboxPolicy, workspace: WorkspaceLease): Promise<SandboxLease>;
  exec(lease: SandboxLease, command: CommandSpec): Promise<ManagedProcess>; // argv/env/cwd
  connect(lease: SandboxLease): Promise<AuthenticatedControlChannel>;
  dispose(lease: SandboxLease): Promise<ReapReport>; // idempotent; descendants/credentials/scratch
  reconcile(leases: PersistedLease[]): Promise<RecoveryReport>;
}
```

`PreflightResult` records exact provider/toolchain versions, enforced filesystem/network/process/limit features and a test receipt. `ManagedProcess` contains safe PID/creation-time identity, exit/drain promise, process ownership handle and terminate API. `SandboxLease` never includes push/inference/API tokens. Windows uses Job Object handle; Linux cgroup + namespace/supervisor; Mac supervisor + owned process identity, with any missing hard guarantee exposed. Destroying an HTTP connection is not process cancellation. Refuse raw PIDs without identity. Completion is admitted only after processes are proven quiescent; otherwise quarantine and report recovery-needed.

### API capability token handshake

Proposed endpoints, not present today: interactive/API session requests `POST /api/execution/leases` with task + device proof; API checks execute authorization and repo/project scope, records idempotent run, returns signed/opaque short-lived capability with audience `openlinear-sidecar`, run binding, policy hash, expiry and jti. The parent passes it through authenticated IPC/inherited private descriptor, never argv, URL query, runner env or general settings. Sidecar proves install ownership with a generated device key and one-time nonce, validates issuer/audience/expiry/jti and scope, then binds a local random session capability to that device/session. Cloud access and local loopback auth are different credentials. Pin accepted origins/hosts and authenticate every local operation including reads; prefer a private Unix socket/named pipe when clients permit it. Health may expose only nonsensitive liveness.

Use separate audience/scopes for `progress:append`, `snapshot:read`, `artifact:write`, and `completion:submit`; callback cannot mint PATs, change membership/access, discover arbitrary SCM tokens or update another run. Narrow capabilities on the API, not only in the client. Bind SSE to the same verified local identity/tenant/run and check revocation. Renew/revoke via authenticated API session; logout, membership removal, task cancellation and device revocation invalidate leases. Retry transport failures with bounded deadline; auth/scope errors fail closed. If offline local execution is desired, create a separately authorized local-only lease that cannot pretend cloud task authority.

## Benchmark constraints

Keep correctness, security and paid quality/cost evals separate. Offline fixture benchmark measures monotonic spans: authorize → workspace acquire → preflight → sandbox launch/control handshake → first mocked token → journal mirror → completion/reap. Report cold/warm mirror/toolchain and sandbox separately, concurrency=1 baseline plus bounded contention, p50/p95 sample count with provider/version/platform/policyHash. A 300MB fixture is generated synthetic source, not cloned production data. Measure peak RSS, disk, pids, bytes and cleanup latency; include rejected preflight and denied egress overhead. Do not disable isolation/network policy or use host credentials to hit a latency budget. No comparison that mixes trusted-host and enforced runs without labeling. No claimed 2.7s/6h/2M-token result from the present scripts; they are placeholders. Performance cannot waive a boundary failure. Paid/provider end-to-end runs remain a separate explicitly authorized activity.

Focused event demultiplexing can land independently: filter raw SDK events using explicit direct/nested session ownership before decode; ignore unscoped events except documented server liveness; preserve own v1/v2 messages, tools, usage, errors and terminal events with interleaved-session tests. Full OS sandbox and credential/desktop bootstrap changes require the interfaces and cross-platform acceptance gates above. Audit completion does not establish that execution is safe today.
