Contract:
  GET /api/search?q=<>&types=tasks,projects,teams&limit=20
    401 if no Bearer token
    400 if q.length < 2
    400 if invalid types/limit
    429 if >30 req/min/user
    200 -> { tasks: [{id,title,identifier,type:'task'}, ...],
             projects: [{id,name,type:'project'}, ...],
             teams: [{id,name,key,type:'team'}, ...] }

Scoping (all enforced via Prisma where-clauses, no raw SQL):
  tasks    : teamId IN (getUserTeamIds(req.userId)) AND archived=false
             AND (title|description|identifier ILIKE %q% via mode:'insensitive')
  projects : projectTeams.some({ teamId IN userTeamIds })
             AND (name|description ILIKE %q%)
  teams    : members.some({ userId: req.userId })
             AND (name|key|description ILIKE %q%)

Cross-tenant safety:
  - getUserTeamIds is the canonical source (T7); no fallback to "any team"
  - When user has 0 team memberships, tasks/projects short-circuit to [] (no Prisma query fired)
  - Team search is gated solely on TeamMember row, never on user-supplied teamId

Limit distribution:
  perType = floor(limit / types.length); e.g. 20 / 3 → 6 each (min 1)

Rate limit:
  express-rate-limit, windowMs=60_000, limit=30
  keyGenerator returns AuthRequest.userId (mounted AFTER requireAuth so userId is set)
  Returns { error:'rate_limited', scope:'search', retryAfterSeconds:60 }
