- Destructured `searchQuery = ""` in hook signature.
- Added derivation:
  ```ts
  const deferredSearchQuery = useDeferredValue(searchQuery)
  const filteredTasks = useMemo(() => {
    const q = deferredSearchQuery.trim().toLowerCase()
    if (q.length < 1) return tasks
    return tasks.filter((task) => {
      const title = (task.title || "").toLowerCase()
      const identifier = (task.identifier || "").toLowerCase()
      return title.includes(q) || identifier.includes(q)
    })
  }, [tasks, deferredSearchQuery])
  ```
- Updated `getTasksByStatus` to filter from `filteredTasks` instead of `tasks` — preserves existing column groupings while applying search.

### apps/desktop-ui/components/board/kanban-board.tsx
- No code change needed: `KanbanBoard(props: KanbanBoardProps)` already spreads props through to `useKanbanBoard(props)`. Adding `searchQuery` to `KanbanBoardProps` automatically propagates.

## Behaviour

- Empty search ("") → returns full `tasks` (no filtering).
- Non-empty (length ≥ 1) → case-insensitive substring match on `title` OR `identifier` (e.g. "OL-12").
- Filter is debounced via React's `useDeferredValue` — keystrokes do not block the input, board updates lazily.
- Status grouping (todo/in_progress/done/cancelled) unchanged — applied AFTER search filter via `getTasksByStatus`.
- Pure client-side; no new fetch path. No new API surface.
