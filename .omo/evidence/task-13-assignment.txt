QA Scenario: Status change emits ActivityLog row + SSE event
----------------------------------------------------------------------

Code path (PATCH /api/tasks/:id with body { status: 'in_progress' }):

  - existing.status === 'todo'
  - statusChanged === true
  - logActivity({ action: 'task_status_changed',
                  payload: { from: 'todo', to: 'in_progress', title } })
  - logActivity → activityLog row inserted; broadcastToTeam emits
    `activity:created` SSE event to every connected member of the task's team.
  - If existing.creatorId !== req.userId:
      createNotification({ type: 'status_change', recipient: creatorId })
      → broadcastToUser(creatorId, 'notification:created', row)

GET /api/activity?taskId=<id> returns the row, ordered by createdAt desc.

----------------------------------------------------------------------
Anti-spam guarantees enforced
----------------------------------------------------------------------

  createNotification early-returns when recipientUserId === actorUserId,
  so the actor never gets notified about their own action.

  logActivity wraps prisma.activityLog.create in try/catch — failures emit
  a `[activity] failed to log — continuing` warning but do NOT propagate,
  so the mutation handler always returns success to the client.

  createNotification likewise wraps prisma.notification.create in try/catch
  with an empty handler (intentional, justified in code).
